配套方案：[easy-workflow OA 化改造技术方案](../specs/2026-10-20-easy-workflow-oa-design.md)。本计划把方案拆成可独立上线、可验收的阶段与任务；所有工期为**人日/区间**，假设见文末。

## 目标与交付范围

**项目目标**：在不推翻现有流程语义的前提下，把 easy-workflow 升级为可上线的 OA 审批平台；身份、组织、角色、登录接 `ark-iam`；补齐表单、附件、加签、抄送、委托、依次/比例审批、通知、SLA、审计、版本治理、测试与可观测。

**本期范围（P0–P5）**：
- 认证/租户/RBAC：OIDC 本地验签、tenant 隔离、任务/实例/定义级授权、目录代理、单点登出。
- 引擎加固：不可变版本、实例钉版本、事务/幂等/乐观锁、自由驳回校验、表达式引擎、后端定义校验、`GetTaskInfo` 修复。
- OA 能力：表单引擎、附件、发起/审批工作台、进度/时间线/评论。
- 审批能力：或签/会签/依次/比例、前/后加签、抄送、委托、转办留痕、批量、撤回、终止/挂起、优先级。
- 通知/审计/SLA：outbox、站内信/邮件/IM、催办、超时升级、审计查询/导出、归档。
- 可观测/交付：指标/日志/链路/告警、压测、安全测试、CI、迁移与回滚手册。

**非目标（P6/另立项）**：完整 BPMN 2.0、子流程/调用活动、边界定时/消息/信号事件、原生移动端、AI 辅助审批、跨租户集团报表、多地域双活。原因见方案“目标与非目标”。

**成功标准**：
- 所有业务 API 默认拒绝匿名；权限矩阵 0 越权；跨租户 0 泄露。
- 发布新流程版本不影响在途实例；节点改名/删除有回归用例。
- 请假/报销/采购 3 条样例流程端到端跑通，含表单、附件、会签/加签/抄送/委托。
- 2 倍峰值压测 P99 达标；审计覆盖率 100%；迁移对账 0 丢失。
- 试点租户上线 2 周无 P0/P1 事故，再扩租户。

## 交付原则

1. **每阶段可独立上线**：P0 不改行为；P1 先 `AUTH_MODE=optional` 再 `enforce`；P2 版本化在开关后启用；P3/P4 按租户灰度。
2. **只做加法迁移**：P1/P2 新增列可空/默认、新增表；不删旧列/旧表；旧二进制可读新数据。
3. **Feature flag 优先**：`auth.enforce`、`engine.versioned`、`oa.forms`、`oa.addsign`、`notify.outbox`、`sla.enabled` 均可独立关停。
4. **先测试后切换**：每个 P0 修复先补回归用例；迁移先在 staging 全量演练。
5. **Definition of Done**：代码 + 单测/集成测试 + 迁移脚本 + 指标/日志 + 文档 + 回滚开关 + 评审通过；缺一不算完成。
6. **安全左移**：认证/授权/表达式/上传/审计在开发阶段过威胁建模与 authz 矩阵；上线前渗透测试。

## 数据迁移与发布

**迁移步骤**：
1. **备份**：MySQL 全量 + binlog 位点；对象存储清单；记录行数/校验和。
2. **Pre-check**：重复 NodeID/多开始节点/空处理人/环/`prev_node_id IS NULL`/超长变量；`proc_execution` 唯一键冲突、`proc_inst_variable` 重复 key、`proc_inst` 活跃业务键冲突；生成报告并去重/规范化。
3. **迁移 P1**：加 `tenant_id`/审计列/索引；回填默认租户；不改变行为；旧二进制可运行。
4. **迁移 P2**：建 `proc_def_version`/`proc_execution` 版本列；从 `proc_def` 回填当前版本；保留旧 `proc_execution`；开关 `engine.versioned=false` 先部署，再打开。
5. **迁移 P3–P5**：表单/附件/加签/CC/委托/outbox/审计/SLA 表；全部加法。
6. **对账**：定义数/版本数/实例数/任务数/金额汇总/附件数；抽样 1% 逐条比对；差异必须解释或修补。
7. **切换**：按租户/开关灰度；观察指标；确认后扩大。
8. **清算**：旧 `/process` 零调用 2 个 release 后下线；旧列/表清理单独审批。

**回滚**：
- 代码回退到上一版本；新列/新表被忽略（只做加法）。
- `AUTH_MODE` 从 `enforce` 临时降为 `optional`（仅限事故窗口，需安全审批）。
- 版本化开关关闭后，旧代码读 `proc_def.resource`（双写保持最新版本）。
- 已按新格式写入的数据：旧代码必须能读；若不能，回滚需数据修补或前滚。
- 不可逆动作（删列/删表/切主/删旧 API）必须单独变更单 + 备份 + 审批。

**发布检查清单**：
- [ ] 迁移在 staging 全量演练通过，耗时/锁表时间可接受。
- [ ] 备份可恢复演练通过；RTO/RPO 达标。
- [ ] feature flag 默认值正确；回滚步骤演练过。
- [ ] 监控/告警/值班人已就位。
- [ ] 试点租户名单/联系人/回滚窗口确认。
- [ ] 安全评审/渗透测试无高危。
- [ ] 审计覆盖率/权限矩阵报告归档。
